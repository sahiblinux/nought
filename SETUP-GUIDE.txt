 STEP 5B — DEPLOY TO GITHUB PAGES (alternative)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

GitHub Pages can ONLY serve static files. It CANNOT run
your API routes. So you need TWO platforms:

  Frontend → GitHub Pages (static files)
  API      → Vercel (serverless functions)

─── 5B.1 — Deploy API to Vercel ───

1. Go to https://vercel.com and sign in with GitHub

2. Click "Add New" → "Project" → import your nought-code repo

3. Configure:
   - Framework: Other
   - Root directory: . (leave default)
   - Build command: npm run build
   - Output directory: dist

4. Add the same 5 environment variables as in Step 5A.2

5. Deploy. Note your Vercel URL, e.g.:
   https://nought-code.vercel.app

─── 5B.2 — Deploy frontend to GitHub Pages ───

1. In the code, open `.env` and add:

   VITE_API_BASE=https://nought-code.vercel.app

   (This tells the frontend to call Vercel for API requests)

2. Open `vite.config.ts` and add the `base` option:

   Change the return block to include:
     base: '/nought-code/',

   (This is needed because GitHub Pages serves from
   /nought-code/ not /)

3. Rebuild:  npm run build

4. Push to GitHub:  git add . && git commit && git push

5. Go to your GitHub repo → Settings → Pages

6. Under "Source", select "GitHub Actions" or
   "Deploy from a branch" → main → / (root)

7. Wait 1-2 minutes. Your site will be at:
   https://YOUR-USERNAME.github.io/nought-code/

 STEP 7 — OPTIONAL: EMAIL FOR SIGN-UP
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Right now, when users sign up, the verification code is
shown on-screen (in a highlighted box). This works fine
for testing.

To send real emails:

1. Go to https://resend.com and create a free account
   (100 emails/day free)

2. Get your API key from the Resend dashboard

3. Verify your sending domain in Resend
   (they'll give you DNS records to add)

4. Add to your deployment platform's environment variables:

   RESEND_API_KEY=re_xxxxxxxx
   MAIL_FROM=Nought <noreply@yourdomain.com>

5. Redeploy (push a commit or retry the deployment)

Now users get real verification emails instead of on-screen codes.
